## 一句话

> **推荐算法知道你最近在看什么，但你自己知道吗？**

> **我们不改变你的知乎信息流，只把你的信息流变得可见。**

---

## 1. 用户痛点是什么

用户每天在知乎读几十篇内容，但只能感知「这一篇」。没有人能回答：

- 我最近反复在接触哪几个核心思想？
- 哪些主题正在上升、哪些在消失？
- 我最近的信息暴露是不是高度集中在少数概念上？

平台知道，用户不知道。这是一个**信息不对称**，不是一个功能缺失。

## 2. AI 在其中真正解决了什么

不是"生成摘要"，而是**判断一篇内容真正的核心思想是什么**。

这是整个产品成立与否的唯一技术前提：判错一次，占比、趋势、集中度全线污染。

## 3. 为什么普通关键词统计不够

100 条盲测集，其中 20 条是专门设计的表层陷阱（陷阱词重复 8–20 次）：

| 方法 | 对抗题 | 重大误分类率 | 严格 primary 准确率 |
| :- | :- | :- | :- |
| 关键词统计 | 17/20 | **0.295** | 0.250 |
| **Claude 实验分类器** | **20/20** | **0** | 0.889 |

> ⚠️ **这一行是 Claude 实验分类器的成绩，不是知流的产品准确率。**
> 它回答的问题是「语言理解能不能打过关键词统计」——**能**，而且差距很大。
> 它**不能**用来宣称知流的准确率是 88.9%：出货产品跑的是本地 `qwen2.5:14b`，
> 语料和评分口径也完全不同。产品自己的选型结果见
> [`docs/MODEL_SELECTION.md`](MODEL_SELECTION.md)：29 条验收集上 14B 主分 1.83/2、
> 0 条判错领域、6/6 多主题——**那是另一套数字，不要混着念。**

关键词方法不是不够精确，是**系统性地被表层词欺骗**——每三篇就有一篇被判到
一个问题意识完全不同的大类。这一条有充分数据支撑。

**但下一条我们测错了，必须一起讲。**

## 4. 知乎官方 API 在这里起什么作用（**结论已被自己的实验修正两次**）

我们先后测了两种用法，**两种都没能证明它能提升判断准确率**：

**第一次**：把知乎语料当**判别器**（算原文与候选语义邻域的分布相似度，谁高选谁）。
→ 在 LLM 之上重排，修对 1 条、改坏 12 条。失败。

**第二次**：把知乎语料当**证据**，最终判断仍交给 LLM（`原文 + 候选 + 知乎社区讨论 → LLM 裁决`）。
→ 100 条盲测，四档证据全部与 LLM-only 无显著差异（McNemar p 从 0.125 到 1.000）。

**根本原因是没有 headroom**：LLM-only 在 20 条对抗题上已经 20/20，
重大误分类率 0。我们造不出一个能骗过它的样本，也就无从证明证据有用。

完整数据见 [`../BLIND_TEST.md`](../BLIND_TEST.md)。

### 那知乎 API 现在的定位是什么

按证据，只剩三条站得住：

1. **可解释性与溯源**：面板可以给出"为什么判成这个概念"，并附上知乎社区里
   真实的同类讨论。这是 LLM 直接分类给不了的产品能力（不是准确率能力）。
2. **校准**：完整证据档的 ECE 从 0.128 降到 0.090，是本轮唯一稳定的量化收益。
3. **承认不确定**：歧义题严格准确率 8/11 → 10/11，ambiguous 识别 2/17 → 4/17。

**不再宣称**：知乎 API 能纠正 AI 的语义误判。

## 5. 为什么离开知乎语境后效果会下降

**这条现在只对"可解释性"成立，对"准确率"不成立。**

面板要展示的是「你读的这篇，和知乎社区里哪一类讨论是同一个问题意识」，
这个语境只有知乎自己的语料能提供——「社恐」「上岸」「内耗」这些社区方言，
以及它们与具体场景的绑定关系，站外语料给不了。

但如果有人问"换个语料准确率会掉多少"，诚实的回答是：
**测不出来，因为接不接知乎语料，准确率本来就没有显著差别。**

## 6. 我们怎么证明——以及我们证伪了什么

30 条 benchmark，**gold label 由一个独立 agent 在看不到算法实现的前提下盲写**，
知乎语料 fixture 由**另一个独立 agent** 撰写（既不知道文章，也不知道算法），
Baseline B 由**第三个独立 agent** 在只看得到标题正文、看不到答案的条件下分类。

三个 arm **共用同一份候选召回**（同一份 cues，且 cues 在 gold 集产出之前就已 commit 冻结），
唯一变量是判定方式 —— 所以差值可以干净地归因到知乎语义 Grounding。

主指标：**Major Misclassification Rate**（是否把文章归到问题意识完全不同的大类），
而不是关键词 F1。我们怕的不是漏标，是判错。

我们做的是一次**有纪律的盲测**，而不是挑几个好看的 demo：

- 100 条样本由 **4 位独立撰写者**产出，均不写答案
- gold 由**两位独立标注者**盲标，一致性 93/100
- 裁决指令在盲测集**首次使用之前冻结**，SHA-256 存档
- 参数全部在另一套 DEV 集上开发，盲测后未再调整
- 报告 Wilson 区间与配对 McNemar 检验，不拿 3 道题的差当结论

**结果对我们不利，我们照样公布：**

| 主张 | 结论 |
| :- | :- |
| 关键词方法会系统性误判 | ✅ 成立（重大误分类率 0.295 vs 0）。**注意：这批数字来自 Claude 实验分类器的 100 条盲测，不是产品准确率。** 产品自己的选型结果是另一套数字，见 `docs/MODEL_SELECTION.md`，两者不可互换引用 |
| 知乎证据能提升判断准确率 | ❌ **未能证明**，四档证据全部 p > 0.05 |
| AI 会被表层关键词带偏 | ❌ **被证伪**，LLM 在 20 条对抗题上 20/20 |
| 证据越多越好 | ❌ **反了**，只给标题（0.926）优于完整证据（0.877） |
| 知乎证据改善校准与不确定性识别 | ✅ 小幅成立（ECE 0.128→0.090） |

如果评委问「你们的核心假设成立吗」，正确答案是：
**关于关键词的那一半成立，关于 AI 的那一半被我们自己证伪了，数据和脚本都在仓库里。**

## 7. 为什么「信息集中度」不是伪科学

因为它**只声称它能声称的东西**：

- 它测量的是「最近 N 篇有效阅读中，标准化概念分布的集中程度」，
  用归一化 Shannon 熵的反向值，公式完全公开、可复算；
- 它**不**声称用户陷入信息茧房；
- 它**不**归因推荐算法；
- 它**不**判断好坏——高集中度同样可能只是用户正在系统性地学一个主题。

工程上还有两条硬约束：

- **每篇文章总权重恒为 1**，再平分给它的概念。否则"被提取出 3 个概念的文章"
  会获得 3 倍影响，而概念数量只反映模型的犹豫程度，不反映阅读量。
- **样本 < 5 篇不出分**，只显示「数据积累中」。不用 2 篇文章算出一个看起来很精确的数字。

配色也遵守这条边界：色调只在同一冷色系内位移，**不用绿=健康红=危险的交通灯**。

## 8. 用户为什么会愿意长期留着这个小面板

- 默认折叠成一行，不打断阅读；
- 不推送、不打扰、不告诉你该看什么；
- 它提供的是**别处拿不到的信息**——你自己的信息结构；
- **长期阅读画像和跨页面聚合只保存在本地**，服务端不接收任何用户状态。

隐私边界一句话：

> **长期阅读画像和跨页面聚合只保存在本地。**

请求体有强制字段白名单，只允许 `contentId` / `contentType` / `title` / `text`，
出现 `userId`、`sessionId`、`history`、`previousConcepts`、`concentration` 或完整 URL
一律 400 拒绝（12 条可执行断言覆盖）。

**但不要说"服务器无法看到用户轨迹"**——逐篇请求序列加时间戳在网络层仍可被关联，
代码层面阻止不了。要把它从承诺变成架构保证，需要把裁决下沉到客户端、
服务端只每日下发语料包，那一步**尚未完成**。评委追问时直接这么答。

## 9. Demo 20 秒内最强 Wow Moment（口径已按盲测结果收紧）

打开一篇满屏「女性/男性/约会/外貌」的知乎回答，并排展示两种方法：

```
关键词统计            →  性别议题        ✘
知流（LLM + 知乎证据） →  社交焦虑        ✔
                          负面评价恐惧

判据（来自知乎社区真实讨论）：
  「害怕被否定，所以我从来不在会上提问」
  「社交焦虑和内向不是一回事——怕的是被注意到之后被评价」
```

**20 秒内观众看到的是：同一篇文章，两种方法给出完全不同的答案，
而知流能把「凭什么这么判」摊开给你看，判据是知乎社区里真实的同类讨论。**

然后左上角面板实时更新——那是"信息流变得可见"的瞬间。

> **演示纪律**：这一步展示的是「相对关键词方法的增益」（已验证，0.295 → 0 重大误分类）
> 和「可解释性」（LLM 直接分类给不了）。
> **不要宣称它比直接问 LLM 更准**——我们做过 100 条盲测，没有显著差异。
> 评委如果追问，直接给 `BLIND_TEST.md`。承认这一点比被当场问穿要好得多。
