# Information Concentration V0.1

## 1. 指标要回答的问题

> 最近一段有效阅读中，用户的信息暴露是否越来越集中在少数核心概念上？

它**不回答**：

- 用户是否陷入“信息茧房”；
- 推荐算法是否造成了该结构；
- 这种集中是好还是坏。

正式 UI 名称建议：**信息集中度**。

## 2. 基本窗口

V0.1：最近 `N = 20` 篇有效阅读内容。

少于 5 篇时：

```text
数据积累中
```

不显示精确 0–100 分数。

## 3. 每篇文章如何贡献权重

一篇文章最终有 1–3 个概念，但每篇文章总贡献固定为 1，避免“提取了 3 个标签的文章”权重大于“只提取 1 个标签的文章”。

例如：

```text
文章 A → [社交焦虑]                 → 1.00
文章 B → [社交焦虑, 负面评价恐惧] → 0.50 + 0.50
文章 C → [就业, 稳定, 风险]        → 0.333 + 0.333 + 0.333
```

低置信度概念可以按 confidence 做轻微权重调整，但 P0 建议先不用，保持可解释。

## 4. 聚合分布

窗口内累计每个 canonical concept 的权重：

```text
w_i
```

归一化：

```text
p_i = w_i / Σw
```

得到概念暴露分布。

## 5. 集中度公式

> ⚠️ **本节描述的归一化熵方案已于第四轮废弃。**
> 它有致命的样本量依赖：行为完全不变的读者 n=5 时中位约 43、n=20 时约 21，
> 分数腰斩却与读了什么无关，这个数字因此无法跨时间解释。
>
> **现行定义是 Simpson 指数 `C = Σpᵢ²`，固定窗口 20 篇，<10 不出分、10–19 标初步。**
> 见 `README.md` 的「指标定义」一节与 `packages/core/src/concentration.ts`。
> 下面保留原方案只为记录设计演变，**不要照它实现**。

~~P0 推荐使用**归一化 Shannon Entropy 的反向值**~~：

```text
H = -Σ p_i ln(p_i)
H_norm = H / ln(K)
Concentration = 100 × (1 - H_norm)
```

其中：

- `K` = 当前窗口出现的 canonical concepts 数量；
- 分布越均匀，Entropy 越高，Concentration 越低；
- 少数概念占比越高，Concentration 越高。

边界：

- `K <= 1` 且已有足够样本：Concentration = 100；
- 样本不足 5 篇：不显示分数；
- UI 取整数。

## 6. 为什么不用“最高关键词占比 × 100”

因为：

```text
40 / 30 / 30
```

和

```text
40 / 10 / 10 / 10 / 10 / 10 / 10
```

最高概念都是 40%，但整体分布集中程度明显不同。Entropy 会考虑完整分布。

## 7. Trend

Trend 不需要复杂时间序列。

将最近 20 篇分为：

- 前 10 篇；
- 后 10 篇。

对 Top concepts 计算两段暴露占比：

```text
Δ = p_recent - p_previous
```

V0.1 UI：

- `Δ >= +0.05` → ↑
- `Δ <= -0.05` → ↓
- 其他 → →

阈值后续用真实数据调。

## 8. 面板颜色（可选）

颜色只是视觉编码，不是风险评级。

建议：

- 关闭时：固定中性色；
- 开启时：随 Concentration 连续改变色调/明度；
- 不显示“安全/警告/危险”；
- 不用绿黄红交通灯。

文案始终保持：

> 最近信息结构更集中 / 更分散

而不是：

> 你正在陷入信息茧房

## 9. 解释层

用户点击分数可看到一句解释：

```text
信息集中度根据最近 20 篇内容中核心概念的分布计算。
它只描述你最近接触的信息是否集中，不判断原因，也不代表好坏。
```

## 10. 后续验证

需要用模拟分布做单元测试：

- 单一概念 → 接近 100；
- 两概念 50/50 → 低于单一概念；
- 多概念均匀 → 接近 0；
- 少数概念极强 + 长尾 → 中高；
- canonicalization 前后不能出现非预期大跳变。
