# PRD V0.1 — 知乎信息暴露面板

> ⚠️ **历史文档：这是第一 / 第二轮的原始设计，其中的核心技术假设已被后续实验证伪。**
>
> 具体来说：把知乎语料当**判别器**（第一轮）在 LLM 之上重排是**修对 1 条、改坏 12 条**；
> 把它当**证据层**（第二轮 100 条盲测）四个层级两两之间 McNemar p 0.125–1.000，
> **测不出增益**。因此主链路现在是 LLM-only，知乎语料只保留"解释与溯源"的角色。
>
> 本文里凡是把「知乎 Grounding 判别」「Zhida 复核」写成产品组成部分的段落，
> 都应读作**当初的设想**，不是现在的实现。配额、端点、模型名等数字**未在本机复核**。
> 当前的真实状态见 [`../README.md`](../README.md) 的「当前状态与诚实边界」、
> [`MODEL_SELECTION.md`](MODEL_SELECTION.md) 与 [`../BLIND_TEST.md`](../BLIND_TEST.md)。


## 1. 问题

用户在知乎持续消费信息，但通常只能感知“这一篇内容”，很难看见最近一段时间里：

- 哪些核心思想反复出现；
- 哪些主题正在明显上升/下降；
- 自己最近的信息暴露是否高度集中在少数概念上。

平台知道用户看过什么，但用户自己缺少一个持续、低打扰的可视化窗口。

更难的问题是：如果只让大模型对每篇文章直接生成关键词，语义误判会污染整个面板。例如一篇大量出现“女性、约会、异性评价”的文章，核心可能是“社交焦虑/害怕负面评价”，而不是“性别议题”。因此 V0.1 的技术核心不是简单关键词抽取，而是**核心思想的语义校准与消歧**。

## 2. 产品目标

让用户在不改变原有知乎使用习惯的前提下，实时看见自己最近的信息暴露结构。

### 目标体验

> 用户原本只是在刷 Feed，后来开始“看见自己的 Feed”。

## 3. 非目标

V0.1 明确不做：

- 反推荐 / 对冲推荐；
- 修改或重排知乎 Feed；
- “你应该看什么”的建议；
- 政治/价值立场打分；
- 认知偏差诊断；
- “信息茧房程度”的因果判断；
- 文章质量、可信度或作者权威评分；
- K 线、持仓、收益率等金融业务隐喻；
- 复杂 OAuth 用户画像（可作为后续增强，但不是 P0）。

## 4. 目标用户

知乎 C 端高频阅读用户，尤其是：

- 每天连续浏览多篇回答/文章；
- 会围绕一个议题深挖；
- 对“最近自己都在看什么”有自我观察需求；
- 希望保留自主判断，而不是再接受一套新的推荐算法。

## 5. 核心用户流程

### 5.1 有效阅读

页面满足以下条件后，才生成一次信息暴露记录：

- 域名属于知乎；
- 页面识别为回答或文章；
- 正文提取成功；
- 页面处于可见状态；
- 累计有效停留 ≥ 8 秒（V0.1 默认，可配置）；
- 同一 URL / ContentID 在短时间内不重复计入。

后续可加入滚动深度，但不阻塞 V0.1。

### 5.2 核心思想识别

输入：当前文章标题 + 正文（必要时截断）。

输出：1–3 个标准化核心概念，例如：

```json
{
  "concepts": [
    {"label": "社交焦虑", "confidence": 0.82},
    {"label": "负面评价恐惧", "confidence": 0.67}
  ]
}
```

该结果必须经过知乎语义 Grounding，不能只由第一遍模型自由生成。

### 5.3 面板

默认位置：知乎页面左上区域，尽量避开正文和主要导航；最终位置由实测确定。

默认折叠态：

```text
信息集中度 68
```

展开态最少显示：

```text
今日信息
稳定      26%
就业      20%
风险      15%
AI         9%

趋势
稳定 ↑   就业 ↑   AI ↓

信息集中度 68
```

### 5.4 可选色调

设置项：`根据信息集中度调整面板色调`。

- 默认可以关闭或使用很克制的变化；
- 不使用“绿=健康 / 红=危险”的强价值判断；
- 颜色只表达“当前信息结构更集中/更分散”。

## 6. 时间窗口

P0 先支持一个固定滚动窗口：最近 **20 篇有效阅读内容**。

原因：

- 比按自然日更适合 Demo；
- 对不同阅读频率更稳定；
- 不需要复杂日历逻辑。

P1 再加入：今日 / 近 7 日 / 最近 N 篇切换。

## 7. 核心指标

P0 仅三个：

1. **Top Concepts**：窗口内标准化概念的暴露占比；
2. **Trend**：概念在窗口前半 vs 后半的变化方向；
3. **Information Concentration**：概念分布的集中程度，0–100，仅描述分布，不等于“信息茧房”。

## 8. 成功标准

### 产品成功

一个首次看到 Demo 的人能在 20 秒内理解：

> “它没有改变推荐，只是在实时显示我最近究竟反复接触了哪些核心思想。”

### 技术成功

- 不把明显的表层词汇误当核心思想；
- 同义表达能稳定合并；
- 低置信度内容不会强行污染统计；
- API Secret 不进入浏览器扩展源码；
- 历史默认本地保存。

### 比赛 Demo 成功

演示一篇容易误判的文章：

```text
第一遍候选：性别议题 / 社交焦虑 / 亲密关系
        ↓
知乎语义 Grounding
        ↓
最终：社交焦虑 / 负面评价恐惧
```

随后面板实时更新。

## 9. P0 / P1 / Later

### P0 — 必须完成

- Chrome Extension 基础骨架；
- 知乎文章/回答识别；
- 有效阅读检测；
- 正文提取；
- 候选概念提取；
- Zhihu Search API Grounding；
- 1–3 个 final concepts；
- 本地历史；
- Top concepts；
- Trend；
- Information Concentration；
- 左上角 mini dashboard；
- Mock/测试数据模式；
- Secret server-side。

### P1 — 有余力再做

- 低置信度时调用 Zhida Agent 复核；
- 气泡图视图；
- 面板色调随集中度变化；
- 今日 / 近 7 日窗口；
- 设置页；
- 导出本地摘要。

### Later

- OAuth 长期兴趣背景；
- 跨设备同步（需重新评估隐私）；
- 更多内容平台；
- 用户主动修正标签，反哺个人词典。

## 10. 最大风险

1. **语义标签漂移**：同义概念被拆散；
2. **中心思想误判**：表层人物/关键词压过真正主题；
3. **集中度被误解为价值判断**；
4. **正文 DOM 变化导致抓取失效**；
5. **Access Secret 泄露**；
6. **每篇多次 Search API 导致不必要调用量**。

每项在技术文档中给出对应缓解方案。
